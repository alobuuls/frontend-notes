# 🖥️ ¿QUÉ ES FRONTEND?

### 🎤 Respuesta para entrevista

> **Frontend es la parte de una aplicación con la que interactúa directamente el usuario.** Se encarga de construir la interfaz, manejar las interacciones y mostrar la información que recibe del backend. Normalmente utiliza tecnologías como HTML, CSS y JavaScript, además de frameworks como Angular, React o Vue.

> 🧠 **EN SENCILLO**
>
> Frontend = **lo que el usuario ve y utiliza**.

```text
👤 Usuario
   ↓
🖥️ Frontend
   ↓
🌐 API
   ↓
⚙️ Backend
   ↓
🗄️ Base de datos
```

---

# ⚔️ ¿QUÉ DIFERENCIA HAY ENTRE FRONTEND Y BACKEND?

### 🎤 Respuesta para entrevista

> **El frontend se encarga principalmente de la interfaz y la interacción con el usuario, mientras que el backend se encarga de la lógica del servidor, procesamiento de datos, autenticación y comunicación con la base de datos.** Ambos se comunican normalmente mediante APIs.

### 🧠 Ejemplo

| 🖥️ Frontend | ⚙️ Backend             |
| ------------ | ---------------------- |
| 📧 Email     | Recibe credenciales    |
| 🔒 Password  | Valida usuario         |
| `[LOGIN]`    | Consulta base de datos |
|              | Genera token           |
|              | Devuelve respuesta     |

**Frontend:**

```text
📧 Email
🔒 Password
      ↓
   [LOGIN]
```

**Backend:**

```text
Recibe credenciales
        ↓
Valida usuario
        ↓
Consulta base de datos
        ↓
Genera token
        ↓
Devuelve respuesta
```

---

# 📱 ¿QUÉ ES UNA SPA?

SPA significa **Single Page Application**.

### 🎤 Respuesta para entrevista

> Una SPA es una aplicación web que carga inicialmente una página y posteriormente actualiza su contenido dinámicamente sin tener que recargar completamente el documento en cada navegación. Frameworks como Angular, React y Vue permiten construir este tipo de aplicaciones.

### 🧠 Ejemplo

En una página tradicional:

```text
/login
   ↓
nueva página

/users
   ↓
nueva página

/settings
   ↓
nueva página
```

En una SPA:

```text
Aplicación
    ↓
┌──────────────────┐
│      Angular     │
└──────────────────┘
    ↓
cambia solamente
el contenido necesario
```

Por eso al navegar entre rutas puedes sentir que la aplicación **no se está recargando completamente**.

---

# 🌐 ¿QUÉ ES UNA API?

### 🎤 Respuesta para entrevista

> **Una API es una interfaz que permite que diferentes sistemas o aplicaciones se comuniquen entre sí mediante reglas y contratos definidos.** En una aplicación web, el frontend puede utilizar una API para solicitar o enviar información al backend.

### 🧠 Ejemplo

Tu frontend necesita obtener usuarios:

```http
GET /api/users
```

El backend responde:

```json
{
  "users": [
    {
      "id": 1,
      "name": "Alo"
    }
  ]
}
```

Entonces:

```text
Frontend
   ↓
   GET /users
   ↓
API / Backend
   ↓
Base de datos
   ↓
Respuesta JSON
   ↓
Frontend
```

> 💡 **IMPORTANTE**
>
> Una API no necesariamente es REST. REST es un estilo arquitectónico que puede utilizarse para diseñar APIs.

---

# 🏗️ ¿QUÉ ES REST?

REST significa **Representational State Transfer**.

### 🎤 Respuesta para entrevista

> **REST es un estilo arquitectónico para diseñar servicios web utilizando los principios de HTTP.** Organiza la información como recursos y utiliza métodos HTTP como GET, POST, PUT, PATCH y DELETE para interactuar con esos recursos.

Por ejemplo:

```http
GET    /users
GET    /users/10
POST   /users
PUT    /users/10
PATCH  /users/10
DELETE /users/10
```

Aquí `users` representa un **recurso**.

### 🧠 Regla mental

| Método   | Acción                   |
| -------- | ------------------------ |
| `GET`    | → obtener                |
| `POST`   | → crear                  |
| `PUT`    | → reemplazar             |
| `PATCH`  | → modificar parcialmente |
| `DELETE` | → eliminar               |

---

# 🌍 ¿QUÉ ES HTTP?

HTTP significa **HyperText Transfer Protocol**.

### 🎤 Respuesta para entrevista

> **HTTP es un protocolo de comunicación utilizado para transferir información entre clientes y servidores en la web.** Define cómo se realizan las solicitudes y respuestas, incluyendo métodos, headers, body y códigos de estado.

### 🧠 Ejemplo

```text
Cliente
   │
   │ GET /users
   ↓
Servidor
   │
   │ 200 OK
   │
   │ JSON
   ↓
Cliente
```

### 📤 Una petición HTTP puede contener

| Elemento    |                    |
| ----------- | ------------------ |
| **Method**  | Método HTTP        |
| **URL**     | Recurso solicitado |
| **Headers** | Metadatos          |
| **Body**    | Datos enviados     |

### 📥 Y la respuesta

| Elemento        |                    |
| --------------- | ------------------ |
| **Status Code** | Código de estado   |
| **Headers**     | Metadatos          |
| **Body**        | Datos de respuesta |

> 💡 **TIP**
>
> Para entrevista, recuerda esta relación:
>
> **HTTP = protocolo → REST = estilo arquitectónico → API = interfaz de comunicación.**

# 🔐 ¿QUÉ DIFERENCIA HAY ENTRE HTTP Y HTTPS?

### 🎤 Respuesta para entrevista

> **HTTPS es HTTP utilizando una conexión cifrada mediante TLS.** HTTP transmite la información sin ese cifrado, mientras que HTTPS protege los datos durante el transporte y permite verificar la identidad del servidor mediante certificados digitales.

| Protocolo | Característica              |
| --------- | --------------------------- |
| HTTP      | ❌ Sin cifrado de transporte |
| HTTPS     | 🔐 HTTP + TLS               |

Por ejemplo:

```text
http://example.com
```

vs.

```text
https://example.com
```

> 💡 **HTTPS no significa que la aplicación sea automáticamente segura.** Protege principalmente la comunicación entre cliente y servidor.

---

# 📡 ¿QUÉ SON LOS MÉTODOS HTTP?

### 🎤 Respuesta general

> Los métodos HTTP indican qué operación quiere realizar el cliente sobre un recurso.

| Método   | Uso típico             |
| -------- | ---------------------- |
| `GET`    | Obtener                |
| `POST`   | Crear                  |
| `PUT`    | Reemplazar             |
| `PATCH`  | Modificar parcialmente |
| `DELETE` | Eliminar               |

---

# 📥 GET

### 🎤 Respuesta

> **GET se utiliza para solicitar información de un recurso.** No debería utilizarse para modificar información del servidor.

```http
GET /users
```

Obtiene usuarios.

```http
GET /users/15
```

Obtiene el usuario `15`.

---

# 📤 POST

### 🎤 Respuesta

> **POST se utiliza normalmente para crear un nuevo recurso o enviar información al servidor para que la procese.**

```http
POST /users
```

Body:

```json
{
  "name": "Alo",
  "email": "alo@example.com"
}
```

---

# 🔄 PUT

### 🎤 Respuesta

> **PUT se utiliza normalmente para reemplazar completamente un recurso existente por una nueva representación.**

```http
PUT /users/15
```

```json
{
  "name": "Alo",
  "email": "new@example.com",
  "age": 25
}
```

> 🧠 **PUT → reemplazar el recurso completo**

---

# ✏️ PATCH

### 🎤 Respuesta

> **PATCH se utiliza para realizar modificaciones parciales sobre un recurso.**

Por ejemplo, si solamente queremos cambiar el nombre:

```http
PATCH /users/15
```

```json
{
  "name": "Alo Updated"
}
```

No necesitamos enviar todo el usuario.

### 🧠 Diferencia clave

| Método  | Operación               |
| ------- | ----------------------- |
| `PUT`   | 🔄 Reemplazo completo   |
| `PATCH` | ✏️ Modificación parcial |

---

# 🗑️ DELETE

### 🎤 Respuesta

> **DELETE se utiliza para solicitar la eliminación de un recurso.**

```http
DELETE /users/15
```

---

# 🚦 ¿QUÉ SON LOS CÓDIGOS DE ESTADO HTTP?

### 🎤 Respuesta

> **Los códigos de estado HTTP indican el resultado de una petición HTTP.** Permiten saber si la solicitud fue exitosa, si hubo un error del cliente, un problema de autenticación, un recurso inexistente o un error del servidor.

| Rango | Significado        |
| ----- | ------------------ |
| `1xx` | Información        |
| `2xx` | Éxito              |
| `3xx` | Redirección        |
| `4xx` | Error del cliente  |
| `5xx` | Error del servidor |

---

# 🔢 ¿QUÉ DIFERENCIA HAY ENTRE 200, 201, 400, 401, 403, 404 Y 500?

> 🧠 **Esta sí te recomiendo aprenderla muy bien.**

### 🟢 `200 OK`

La petición fue exitosa.

```http
GET /users
→ 200 OK
```

---

### 🟢 `201 Created`

La petición fue exitosa y **se creó un recurso**.

```http
POST /users
→ 201 Created
```

Por ejemplo:

```text
POST /users
      ↓
Usuario creado
      ↓
201 Created
```

---

### 🔴 `400 Bad Request`

El servidor no puede procesar la solicitud porque está mal formada o contiene datos inválidos.

```text
Frontend envía datos incorrectos
            ↓
         400
```

Ejemplo:

```json
{
  "email": "esto-no-es-un-email"
}
```

---

### 🔴 `401 Unauthorized`

Significa que la solicitud **no tiene una autenticación válida**.

```text
No token
Token inválido
Token expirado
        ↓
      401
```

> 💡 **401 = "No sé quién eres / tu autenticación no es válida".**

---

### 🔴 `403 Forbidden`

El servidor entiende quién eres, pero **no tienes permisos suficientes**.

```text
Usuario autenticado
        ↓
No tiene permisos
        ↓
      403
```

Ejemplo:

```text
👤 Usuario normal
       ↓
DELETE /admin/users/10
       ↓
403 Forbidden
```

> 💡 Diferencia clave:

| Código | Problema                  |
| ------ | ------------------------- |
| `401`  | Problema de autenticación |
| `403`  | Problema de autorización  |

---

### 🔴 `404 Not Found`

El recurso solicitado no existe o no se encontró.

```http
GET /users/999999
```

Si ese usuario no existe:

```http
404 Not Found
```

---

### 💀 `500 Internal Server Error`

Hubo un error inesperado en el servidor.

```text
Frontend
   ↓
Backend
   ↓
💥 Error
   ↓
500
```

---

# 📦 ¿QUÉ ES JSON?

JSON significa **JavaScript Object Notation**.

### 🎤 Respuesta

> **JSON es un formato ligero de intercambio de datos basado en una estructura de objetos y arrays. Es muy utilizado para comunicar información entre frontend y backend mediante APIs.**

Ejemplo:

```json
{
  "id": 1,
  "name": "Alo",
  "skills": [
    "Angular",
    "TypeScript",
    "JavaScript"
  ]
}
```

> 💡 Aunque originalmente está basado en la sintaxis de JavaScript, **JSON es un formato independiente del lenguaje**.

# 📡 ¿QUÉ ES UNA PETICIÓN HTTP?

### 🎤 Respuesta

> **Una petición HTTP es un mensaje que un cliente envía a un servidor para solicitar información o realizar una operación.**

Por ejemplo:

```http
GET /api/users
```

Una petición puede contener:

| Elemento | Ejemplo                         |
| -------- | ------------------------------- |
| Método   | `GET`                           |
| URL      | `/api/users`                    |
| Headers  | `Authorization`, `Content-Type` |
| Body     | Datos enviados                  |

Por ejemplo:

```http
POST /api/users
Content-Type: application/json
```

```json
{
  "name": "Alo"
}
```

# 🌐 ¿QUÉ ES CORS?

CORS significa **Cross-Origin Resource Sharing**.

> 🎤 **Respuesta**

> **CORS es un mecanismo de seguridad del navegador que controla si una aplicación web puede realizar solicitudes a un servidor que pertenece a un origen diferente. El servidor puede indicar mediante headers qué orígenes, métodos y headers están permitidos.**

Ejemplo:

```text
Frontend
http://localhost:4200

        ↓

Backend
http://localhost:3000
```

Como tienen diferentes origins:

```text
4200 ≠ 3000
```

el navegador considera que es una solicitud **cross-origin**.

El backend puede responder indicando qué origen permite.

### 🧠 MUY IMPORTANTE

> 💡 CORS es principalmente una **restricción aplicada por los navegadores**.

Por eso muchas veces:

```text
Frontend ❌
   ↓
CORS error
   ↓
Backend
```

no significa necesariamente que el backend esté caído.

# 🍪 ¿QUÉ ES UNA COOKIE?

### 🎤 Respuesta

> **Una cookie es un pequeño dato que un servidor puede almacenar en el navegador del usuario y que puede enviarse automáticamente en determinadas solicitudes posteriores al mismo sitio.** Se utiliza, entre otras cosas, para sesiones, preferencias y autenticación.

Flujo:

```text
Servidor
   ↓
Set-Cookie
   ↓
🍪 navegador
```

Después:

```text
🍪 Cookie
   ↓
petición HTTP
   ↓
Servidor
```

Las cookies pueden tener atributos importantes como:

| Atributo            |   |
| ------------------- | - |
| `HttpOnly`          |   |
| `Secure`            |   |
| `SameSite`          |   |
| `Expires / Max-Age` |   |
| `Domain`            |   |
| `Path`              |   |

> 💡 Por ejemplo, una cookie `HttpOnly` **no puede ser leída directamente por JavaScript del navegador**, lo cual puede ayudar a reducir ciertos riesgos asociados al robo de tokens mediante XSS.

---

# 💾 ¿QUÉ ES LOCALSTORAGE?

### 🎤 Respuesta

> **localStorage es un mecanismo de almacenamiento del navegador que permite guardar datos en forma de pares clave-valor y que permanecen después de cerrar y volver a abrir el navegador, hasta que se eliminen.**

### 📝 Guardar

```ts
localStorage.setItem('theme', 'dark');
```

### 📖 Obtener

```ts
localStorage.getItem('theme');
```

### 🗑️ Eliminar

```ts
localStorage.removeItem('theme');
```

### 🧹 Vaciar

```ts
localStorage.clear();
```

### 🧠 Importante

Los valores se almacenan como strings.

Por eso:

```ts
localStorage.setItem(
  'user',
  JSON.stringify(user)
);
```

Y después:

```ts
const user = JSON.parse(
  localStorage.getItem('user')!
);
```

# 🕐 ¿QUÉ ES SESSIONSTORAGE?

### 🎤 Respuesta

> **sessionStorage es un mecanismo de almacenamiento del navegador similar a localStorage, pero sus datos están asociados a la sesión de navegación de una pestaña y se eliminan cuando esa pestaña se cierra.**

Ejemplo:

```ts
sessionStorage.setItem(
  'step',
  '2'
);
```

Mientras la pestaña siga abierta:

```ts
sessionStorage.getItem('step');
```

puede recuperar el valor.

---

# ⚔️ DIFERENCIA ENTRE COOKIES, LOCALSTORAGE Y SESSIONSTORAGE

> ⭐ Esta comparación es **muy buena para entrevista**.

| Característica                       | 🍪 Cookie          | 💾 localStorage                      | 🕐 sessionStorage    |
| ------------------------------------ | ------------------ | ------------------------------------ | -------------------- |
| Capacidad                            | Pequeña            | Mayor                                | Mayor                |
| Expiración                           | Configurable       | Hasta eliminarla                     | Al cerrar la pestaña |
| Se envía automáticamente al servidor | ✅ Sí, según reglas | ❌ No                                 | ❌ No                 |
| Accesible desde JS                   | ✅ Normalmente      | ✅ Sí                                 | ✅ Sí                 |
| `HttpOnly`                           | ✅ Sí               | ❌ No                                 | ❌ No                 |
| `Secure`                             | ✅ Sí               | ❌ No como atributo de almacenamiento | ❌ No                 |
| Asociada a pestaña                   | No exactamente     | No                                   | ✅ Sí                 |
| Uso típico                           | Sesiones/auth      | Preferencias/datos persistentes      | Datos temporales     |

### 🎤 Respuesta corta para entrevista

> **La principal diferencia es que las cookies pueden enviarse automáticamente en las peticiones HTTP y pueden configurarse con atributos como HttpOnly, Secure y SameSite. localStorage permite almacenar datos persistentes en el navegador pero JavaScript puede acceder a ellos, mientras que sessionStorage funciona de forma similar pero los datos están asociados a la sesión de una pestaña y normalmente desaparecen al cerrarla.**

# ⭐ LAS DIFERENCIAS QUE **SÍ O SÍ** DEBES SABER EXPLICAR

| Diferencia                         | Idea clave                                                         |
| ---------------------------------- | ------------------------------------------------------------------ |
| **401 vs 403**                     | → autenticación vs autorización                                    |
| **PUT vs PATCH**                   | → reemplazo completo vs modificación parcial                       |
| **localStorage vs sessionStorage** | → persistente vs sesión de pestaña                                 |
| **Cookie vs localStorage**         | → cookie puede viajar automáticamente al servidor; localStorage no |
| **HTTP vs HTTPS**                  | → HTTP vs HTTP + TLS                                               |
| **Frontend vs Backend**            | → interfaz/interacción vs lógica/servidor/datos                    |
| **API vs REST**                    | → API es la interfaz; REST es un estilo para diseñar APIs          |

> 🎯 Estas son de las mejores para **practicar en voz alta**, porque en una entrevista técnica normalmente no basta con soltar una definición: te pueden hacer un **“¿y cuál es la diferencia?”** inmediatamente después.
